# 分析步骤（可见的排查过程）与证据化回复

更新：2026-10-05。两部分，对应两个用户诉求：

1. **AI 回复里直接给证据**：排查报错时，不只说"哪里错了"，而是**把出错的那几行原样贴出来**；
   改文件时，给**改动前 / 改动后**的差异（只贴变动的那几行）。用户不用去翻日志。
2. **"分析步骤"**：把模型每一步的**意图 + 它实际做了什么 + 结果摘录**列出来，
   默认折叠、想看就看。用户既能看执行过程，也能一眼判断"卡没卡"。

## 一、为什么这么做（设计判断）

一个运维平台最贵的东西不是"能执行命令"，而是**让人相信它执行的每一步是对的**。
日志和审计里当然有这些数据，但"有"和"看得见"是两回事：

- 用户说"网站卡了"，AI 排查完给一段总结。**可信度来自"我看到证据"，不是"它说它查了"。**
- 出错的那一行源码 / 日志，**原样贴出来**，比任何"根据分析可能是……"都有说服力。
- 改动前后差异贴出来，用户**扫一眼就知道改了什么**，要不要同意心里有底。

这不是花哨功能，是**二级期望（不懂运维的人托管）能不能成立的地基**：
不懂的人凭什么信？就凭"每一步我都看得见、出错的原文我认得出"。

## 二、证据化回复（模型侧，靠提示词约束）

在系统提示的 `HOW TO REPORT CHANGES` 一节里，明确要求模型：

- **诊断报错时**：把命令输出里真正出错的那一行（以及上下各一两行）**原样引用**，
  不要只做转述。
- **改文件时**：给出**统一 diff**——旧行标 `-`、新行标 `+`，**只贴变动的那几行**，
  不贴整个文件。
- 摘录要**短**（几行），每段独立成行。
- **这必须是证据、不是装饰**：只能引用真实看到的输出；**没真看到前后两侧，不许凭记忆编造 diff**。

> 边界：这是提示词层的**行为要求**，不是可强制校验的机制——和既有"不得夸大执行结果"
> 同属一类。它提高默认质量，但不改变权限与审计边界。

## 三、分析步骤（平台侧，派生展示）

### 3.1 数据从哪来（关键：不新增存储）

模型与工具的**原始对话记录**本来就完整存在 `role_turns.messages`；每次调用的完整
请求/响应在 `model_calls`。所以"分析步骤"**不另建表、不重复落盘**，而是在读取轮次时
**从记录里派生**（`ai_ops/turns.py: derive_steps()`）。

这样做的理由：**唯一事实来源**。派生的步骤永远不可能和"模型实际做了什么"漂移，
也不会出现"日志说执行了、步骤说没执行"这种自相矛盾。

### 3.2 派生出的步骤形态

遍历 transcript，按顺序产出：

| kind | 来源 | 字段 |
|---|---|---|
| `thought` | assistant 的**普通文字内容**（非空才出） | `text` |
| `command` | `execute_command` 工具调用（与结果合并） | `command/run_as/asset_id/status/output_excerpt/exit_code/truncated` |
| `search` | `web_search` / `fetch_page` | `query` 或 `url`、`status` |
| `tool_result` | 有结果但本切片内找不到对应调用 | `tool`、`preview` |

- 工具调用先以 `status="proposed"` 出现；**对应的 tool 消息到达后才改为 `done`**，
  并附上结果摘录（`output_excerpt`，上限 2000 字符，超出标"已截断"）。
- **只有模型真的执行过（收到结果）才不再是 proposed** —— 这正好回答"卡没卡"：
  停在 `proposed` 的执行步骤 = 还没跑或还在等。
- `output_truncated`、`status`、`error` 若有则透传（unknown / failed 一眼可见）。

### 3.3 关于"碎碎念"和隐藏推理

- 我们只呈现模型**普通返回的 assistant 文字**——就是它"打算做什么"的一句话。
- **不请求、不伪造隐藏推理**（chain-of-thought）。这既是技术事实，也是边界：
  平台只展示模型真实输出的内容。
- 想让它有"碎碎念"，靠系统提示里那句话要求它**动手前用一句话说明下一步意图**。

### 3.4 前端呈现

控制台聊天/轮次卡片里，步骤以**默认折叠**的"分析步骤（N）"面板出现，展开后每条：
序号、类型标签、状态药丸、以及命令 / 输出摘录。几步就赚，不想看就收起，
**既不淹没结论，又随时可查**。

## 四、接口

- `GET /api/v1/turns/{id}`、`GET /api/v1/roles/{id}/turns` 返回的每个轮次新增字段
  **`steps`**（派生的步骤数组）。**无新增端点、无新增表、无 schema 变更。**
- 完整的模型请求/响应仍在 `GET /api/v1/turns/{id}/model-calls`。

## 五、测试

`tests/test_analysis_steps.py`（8 项）：思考+命令+结果有序；空白 assistant 不产生空步骤；
输出截断标记；unknown 状态与错误透传；检索步骤；**未执行的命令停在 proposed**；
工具参数非法不崩；空记录返回空数组。
