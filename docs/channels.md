# 消息渠道（飞书 / 企业微信 / 微信）

更新：2026-10-03。用户需求（2026-10-02）：**飞书、微信共享角色记忆**；具体接入需验证。
本模块实现**渠道网关的第一层**：身份映射、共享角色记忆、入站转轮次、出站投递。

## 核心结论：共享记忆是"顺带成立"的，不是特例

角色轮次队列（`role_turns`）和按天分层记忆（`role_memory`）**只按 `role_id` 建键**，
从不按渠道。因此**同一个角色无论消息来自 Web、飞书、企业微信还是微信，看到的是同一份
记忆、同一条串行队列**。这正是"渠道共享角色记忆"，它由既有模型直接推出，而不是为渠道
打的补丁。

唯一为渠道新增的是 `role_turns.caller`（schema 8）：记录**是哪个入口产生了这一轮**
（`web` / `channel:feishu` / `channel:weixin` / 告警源…），用于**按来源回读回复**，
**不影响记忆与队列**。

## 数据模型

- `channel_identities(channel, user_id) → role_id, mode, execution_users`：渠道身份到
  角色的绑定。
- `channel_pairing`：一次性配对码（只存哈希，有有效期、单次使用）。
- `channel_messages`：入站/出站消息流水（含 turn_id 与投递时间），用于出站与支持排查。

## 入站流程

```
渠道桥接 → POST /api/v1/channels/inbound {channel,user_id,text,pairing_code?,external_id?}
  ├─ 未配对且无配对码 → 记录入站消息，返回 unpaired，不产生轮次（不自动建角色/不授权）
  ├─ 带配对码 → 校验（未用、未过期）→ 绑定身份 → 继续
  ├─ 已配对 → 按 external_id 去重
  └─ 以 caller="channel:<渠道>" 入队一个普通角色轮次
```

- **一次性配对码就是认证**。新身份在管理员签发配对码前不能做任何事；**未知发件人不会被
  自动建角色或授予权限**。
- `external_id` 是上游稳定事件 ID，重复投递**只保留一条**轮次（`source_id` 幂等）。
- 消息正文**只是提示词**：不能改模式、账号或角色。

## 出站流程（诚实的边界）

```
渠道桥接 → GET /api/v1/channels/outbox?channel=&user_id=&after=&mark=1
```

- 回复**以轮次为准**：轮次进入终态（completed/failed/cancelled/blocked_unknown）才会有
  一条出站；**排队中或失败的轮次绝不编造回复**。非成功轮次如实返回状态（如 `[failed]`）。
- **微信 / 企业微信的对外推送不在本仓库内置**。出站消息以投递形式**保存**，由**外部
  渠道桥接**拉取；我们**不会把"已存储"说成"已发送"**。飞书/微信的真实发送需要各自平台
  凭据与网络出口，属于部署侧。
- 桥接器用**当前管理员凭据**（每次校验重读，支持热轮换）；终端用户看不到该凭据。

## 渠道隔离

- 出站按 `(channel,user_id)` 精确读取：**一个渠道看不到另一个渠道的对话**。
- `GET /api/v1/channels/conversation`（管理员）用于支持排查，可跨渠道读但仅管理员可见。

## API

| 端点 | 鉴权 | 用途 |
| --- | --- | --- |
| `POST /api/v1/channels/pairings` | 管理员 | 为一个角色签发一次性配对码 |
| `GET /api/v1/channels/identities` | 管理员 | 列出渠道身份（可按渠道过滤） |
| `DELETE /api/v1/channels/identities/{channel}/{user_id}` | 管理员 | 解绑（历史保留） |
| `POST /api/v1/channels/inbound` | 渠道桥接 | 转入站消息为角色轮次 |
| `GET /api/v1/channels/outbox` | 渠道桥接 | 按身份拉取角色回复（可标记已投递） |
| `GET /api/v1/channels/conversation` | 管理员 | 单身份会话流水 |

Web 控制台新增「渠道」页：列出身份、签发配对码、说明边界。

## 尚未实现（明确边界）

- **飞书 / 企业微信 / 微信的真实出站发送**：需要平台应用凭据与网络出口，部署侧实现；
  本仓库不内置发送器，也不宣称已验证发送。
- **飞书/微信的入站校验与签名**：真实对接时，桥接侧必须校验平台签名，再调用本网关；
  本网关信任桥接（桥接持有管理员凭据）。
- **富媒体**（图片/文件/卡片）：当前只处理纯文本。
- 渠道身份的角色**切换**需要重新配对（或管理员改绑），当前无自助切换。
