# 敏感信息清理

目标：**命令输出里可能夹带的秘密，不应进入会被读取/回放的派生存储**（模型上下文、审计、任务结果的内联字段）。

## 清理发生在哪里，为什么不清理原始归档

| 数据 | 处理 | 理由 |
| --- | --- | --- |
| `tasks.result` 的内联 `stdout`/`stderr` | **清理** | 这份文本会被当作工具输出喂给模型（`turns.py` 直接把 `tasks.result` 作为 `tool` 消息），也出现在任务详情里。 |
| `audit` 的 `details` | **清理** | 审计里会带上命令文本、载荷、结果摘要；不应把秘密持久化进审计轨迹。 |
| 原始输出归档（`output_chunks`） | **不改写** | 它是运维人员的**逐字节证据**，并有 sha256 校验。改写会静默破坏证据并违反摘要契约。归档的审计只记录大小与 sha256，不含内容。 |

关键边界在**结果写入时**：内联输出在入库前就被脱敏，因此模型从一开始就看不到秘密；模型之后产出的 `final_text`、`model_calls.response` 都源自已脱敏的输入，无需二次清理。

## 识别什么

基于模式，按顺序匹配（先具体后一般）：

- PEM 私钥块（任意类型）→ 整块替换。
- `Authorization:` 头（带或不带 `Bearer`/`Basic`/`Token`）。
- URL 内嵌凭据 `scheme://user:pass@host` → 只遮 `pass`，保留 `scheme://user:` 与 `@host` 便于判断上下文。
- 具名赋值：键名含 `password/passwd/pwd/secret/token/api_key/apikey/access_key/private_key/client_secret/auth_token` 的 `key=value` 或 `key: value`。
- JSON 字符串字段：同上键名的 `"key": "..."`。
- 已知前缀的供应商令牌：`ghp_/gho_/ghu_/ghs_/ghr_`、`sk-`、`xox[baprs]-`、`AKIA…`、`AIza…`。

替换为 `[REDACTED]`，并**尽量保留字段名/前缀**，让读者知道"被遮的是什么"，而不是留下一段无解释的空白。

此外支持**运维声明的字面量**：把已知的某段确切秘密值传给 `redact_text(text, literals=[...])`，即使它不符合任何形状也会被遮掉。

## 不宣称的

- 是**尽力而为**的基于模式的清理，不保证抓到每一种秘密。诚实立场不变：**不要在命令里传秘密**，不要让低权限用户读数据库。
- 不清理原始归档（这是刻意的边界，见上表）。
- 不做语义理解；只做模式与字面量替换。
