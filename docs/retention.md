# 输出保留与磁盘配额

原始 stdout/stderr 归档是控制库里**唯一会无限增长**的数据：单流有 64 MiB 上限，但没有限制任务数量。本模块在不删除"进行中工作证据"的前提下把磁盘占用控制在有界范围内。

## 原则

- **进行中的工作永不被清理。** 只有**已终结**任务的**已 finalize** 归档才可被清理。任务状态为 `succeeded` / `failed` / `cancelled` 才算终结；`unknown` 不在此列，因为运维人员尚未处置、可能还需要那部分原始字节。
- **两道独立的界**：
  1. **时间窗**：超过 `retention_days` 的归档先删。
  2. **字节预算**：总量超过 `max_bytes` 时，从最旧的归档开始驱逐，即使它还在时间窗内。
- **保留下限**：最近 `keep_tasks` 个终结任务无论多旧都保留（下限优先于字节预算——配额是尽力而为，最近工作的证据优先）。
- **上传时分流保护**：存储已超预算时，`chunks` 上传接口直接返回 `413`，避免一条失控命令在清理器运行前把盘写满。某任务**自己的**已存字节不计入自身配额，因此它不会因为自己的早期分块而自我阻塞。
- 清理只删除原始字节，**不重写、不摘要**，且清理动作本身写入审计（事件 `output.pruned`）。

## 配置（环境变量）

| 变量 | 默认 | 含义 |
| --- | --- | --- |
| `AI_OPS_OUTPUT_MAX_BYTES` | 2 GiB | 归档原始字节总量上限 |
| `AI_OPS_OUTPUT_RETENTION_DAYS` | 14 | 时间窗，超过则清理 |
| `AI_OPS_OUTPUT_TASK_KEEP` | 200 | 无条件保留的最近终结任务数 |
| `AI_OPS_RETENTION_ENABLED` | 1 | 是否启用后台定期清理线程 |

## 接口（管理员）

- `GET /api/v1/output/usage`：当前占用、归档数、最旧归档时间及生效策略。
- `POST /api/v1/output/prune`：立即执行一次清理，返回删除任务数/字节数与剩余总量。

## 后台任务

服务启动后有一个 daemon 线程按固定间隔（默认 300 秒）运行清理；任一迭代失败只记录异常类型，不中断服务、不打印载荷。

## 不宣称的

- 不承诺清理器能在任何时刻把占用压到预算之下（保留下限可能使总量超过预算）；只保证有界、不删除在途证据、清理可审计。
- 不承诺磁盘绝不会写满：单流 64 MiB 上限与总量预算仍可能被一次性突发超过，直到清理器运行。
