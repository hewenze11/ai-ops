# 产品简介（写给看代码库的人）

本文件用最少的篇幅说明：**这是什么、它不做什么、以及商业上怎么走**。
技术实现细节见各专项文档，本页只讲定位与边界。

## 一句话

一个**可自托管的 AI 运维底座**：运维把常用账号、主机、提示词配置好，AI 就能
替他在真实主机上执行受控命令、分析告警、总结结果——**执行有边界、凭据有边界、每一步可审计**。

## 设计立场：不自带"运维剧本"

这是本产品最重要的一条理念，也是最容易误解的一条：

- **运维提示词是用户的内容，不是产品的功能。** 定制任务（触发/定时）的核心字段
  就是一个 `prompt` 文本，由用户自由编写。没有、也不打算内置"诊断策略库"。
- 触发时，AI 把这段提示词 + 告警数据当**一次普通角色轮次**处理，
  与聊天、定时任务**共用同一角色、同一串行队列、同一份记忆**。
- 为什么这样设计：运维经验千差万别，**写死的策略一定不适用**。
  产品的价值是"给一个好用的执行底座"，把"怎么写提示词"留给用户——或者，交给付费内容。

## 商业方向（本仓库不含相关内容）

产品技术底座与商业形态分离。两条主要盈利路径：

1. **教学与官网**：教程官网 + 视频课程，手把手教用户使用，
   目标是**让没有运维经验的人也能用它做基础运维**。
2. **订阅制 Skills 库**：作者人工审核的 Skills 库，按月订阅。
   它的价值正是**帮用户把提示词写好**——而不是替代上面的执行底座。

面向**只想读源码的技术用户**：本 README 与 `docs/` 已给出完整实现说明，
不需要购买任何内容也能自行部署、二次开发。

> 商城 / 计费 / 账号体系**本期不实现**，仅在架构上预留对接边界。

## 安全边界（写给评估者）

- 模型**不能**执行任意命令：只有受校验的 `execute_command` 工具，且**本轮授权固定**
  （账号、模式在入队时锁定，模型不可改）。
- 三种模式是**真实工具权限**，不是提示词：`readonly` 轮次根本不下发执行工具。
- 凭据**不进模型上下文**：秘密走秘密文件只读挂载，模型请求与审计都经过脱敏。
- 陌生来信**进不了运维面**：渠道身份必须先由管理员签发一次性配对码。
- 一切以**轮次 + 审计**为准：不把"已存储"说成"已发送"，不编造执行结果。

详见：`docs/model-turns.md`（权限边界）、`docs/credentials.md`（凭据）、
`docs/channels.md`（渠道）、`docs/scrubbing.md`（脱敏）。
