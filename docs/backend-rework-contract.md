# Backend rework API contract (implemented, 2026-10-08)

Existing endpoints remain available. All new read APIs require the existing admin bearer credential; a role_id filter is not authentication.

**Heartbeat sequence follow-up (2026-10-08):** optional `heartbeat_telemetry={session_id,controller,attempt_seq,previous_results}` is now implemented in both local repositories. Exact evidence uses the highest received sequence and up to ten preceding actual attempts, not wall-clock cadence; per-controller/startup streams are isolated, late receipts repair gaps, and receipt is separate from sender ACK. `health.heartbeat.metric=heartbeat_attempt_receipt`, `actual_attempts=last_observable_sequence_window`, with `streams[]`, attempt counts and `updated_at/stale/tail_attempts`. The old window fields below remain backward-compatible and retain their old meaning; they must not be read as exact attempt ratios. Heartbeat logs default to old `view=windows`; new `view=attempts` adds sequence/ACK records and a current `summary`. See [完整字段、限额、降级与边界](heartbeat-telemetry.md).

- `GET /api/v1/operator/attention`: adds `awaiting_approvals`, the complete outstanding approval list ordered oldest first (not limited to the 100 most recent historical tasks). Includes id, asset_id, role_id, turn_id, state, parsed/redacted payload, created_at, updated_at. Admin-only; preserves unknown_executions/stale_leases/offline_assets. Standalone tasks without a current chat turn remain actionable. This attention work queue is complete, unlike the separately paginated logs/history API.
- `GET /api/v1/assets`: existing shape extended with `health` (same object as status below).
- `GET /api/v1/agents/{asset_id}/status`: existing `online/presence/unfinished_tasks`, adds `connection_type`, `health_state` (`healthy/offline/unknown/disabled`), `health_source`, `queue_state` (`waiting_other_controller/busy/idle/offline/unknown`), `busy_by`, `busy_task`, `queued_tasks`, `heartbeat` ({applicable, expected_interval_seconds, window_size:10, observed_slots, successful_slots, success_ratio, missed_ratio, retention_hours:24}). Ratios nullable until evidence available; these measure heartbeat arrivals, NOT network packet loss. The server uses completed **10-second observation windows**, not a claim that Agent sends every 10 seconds. Legacy Agent sends roughly every 3s idle / 2s running plus network delays, so without the optional sequence extension only the following fallback metric is available. `metric=heartbeat_window_arrival`, `interval_source=server_observation_window`, `observation_window_seconds=10`, `expected_interval_seconds=null`, `actual_attempts="unavailable"`; UI label: 最近10个10秒时间窗心跳缺失率（非实际尝试丢失率、非网络丢包率）. Controller identity learned from authenticated claim is stable and does not expire after 30s; only busy presence freshness expires, so long-running tasks do not incorrectly extinguish the queue indicator. local/SSH not agent heartbeat.
- `GET /api/v1/assets/{asset_id}/heartbeats?after=0&limit=100`: `{items:[{seq,asset_id,received_at}],next_after,retention_hours:24}`; limit max 500.
- `GET /api/v1/logs?kind=all&role_id=&asset_id=&before=&limit=100`: `{items:[{id,kind,timestamp,role_id,asset_id,entity_id,event,summary,details}],next_before}`. kind: all/task/alarm/trigger/audit/output. Opaque cursor, max 200, descending stable order. Output = command stdout/stderr archive metadata/preview, not AI chat output; no raw bytes in unified logs. Original audit and output endpoints remain.
- `GET /api/v1/documents/system-asset-inventory?role_id=&execution_users=user1,user2`: admin-only, read-only dynamically generated `{id,name,core:true,read_only:true,derived:true,content,assets}`; never stored as editable document. **Management API filtering:** when execution_users is supplied, exclude assets with no matching account; omission returns all active assets. role_id validates that the role exists but does not implement a role-to-asset ACL. **AI core context:** regenerated on every model call from all active assets, without using the management API's account filter; assets remain visible even if their available_selected_users intersection is empty. Only available_selected_users is intersected with the turn's selected accounts. Both paths exclude retired assets and the disabled local asset, and never include stored credentials. Visibility of the core inventory does not grant execution authority.
- Custom task config extension: optional `notification` (`null` = legacy global fallback; `{enabled:false}` = explicitly off; `{enabled:true,url:"https://...",channel:"auto",console_url:null}` = task-specific result webhook). GET returns redacted url; edit omission or returned masked url preserves existing secret. Never pass URLs into AI event payload/context. Original alert-notify global API retained for legacy configs.

Security findings/fixes: readonly already had server-side dispatch rejection in addition to tool omission; confirm is a real queue gate. Fixed corrupted unknown stored mode fail-open; all Agent/SSH/local claim paths now recheck immutable turn mode, selected account, current asset allowed_users, retirement and local disable. OS account permissions remain the second boundary (no command-content denylist can replace native OS permissions). Skills already require both enabled flag and role_ids binding; no new authority layer is invented. No role-to-asset ACL currently exists: core active-asset inventory remains visible to all roles, even with no selected account. available_selected_users is the selected-account intersection and governs execution only; it is not a read ACL. The admin inventory API's optional execution_users is a convenience filter, not authorization. Admin inventory API without execution_users returns all active assets and is explicitly admin-only. Local host status follows actual worker-thread liveness; no fake agent_presence rows. execution_environment/execution_scope=service_runtime: Docker local execution normally means container, not Docker host. security_notice explicitly warns there is NO control-plane isolation: same-service-account commands may read service-readable credentials and alter DB files. No OS permissions were widened. Windows local refuses any run_as other than the actual service username instead of impersonating identity. SSH is `unknown/ssh_on_demand` rather than falsely offline; no periodic SSH probes added.

Compatibility notes: no approval/unknown-resolution/audit/raw-output APIs removed. Task notification config uses the trigger's immutable snapshot. Existing tasks with no notification use the old global hook; explicit disabled overrides it. Legacy asset-offline global pushes remain for compatibility. Task-specific notification does not automatically subscribe to asset-offline events. Sending uses existing SSRF checks, no redirects and bounded retry. Webhook URL paths are also redacted, as path tokens are credentials. Unified logs retain source IDs; cross-source timestamps are source event timestamps, not a new audit sequence. New source tables heartbeat_samples/controller_observations are created idempotently; existing schema user_version stays 9. Retention prunes heartbeat samples, not audit evidence. Health reads never initiate external connections.

Residual SSRF risk: model fetch_page remains compatible with internal HTTP(S) documentation endpoints, rejects embedded user/password, disables proxies and redirects, and bounds reads. It is NOT a complete SSRF defense: private/metadata/control-plane addresses and DNS rebinding require explicit network egress policy or a future operator-configured allowlist. The stricter webhook validator cannot be blindly reused without breaking legitimate intranet fetching; this rollout does not silently impose public-only browsing. readonly is not a network sandbox.
