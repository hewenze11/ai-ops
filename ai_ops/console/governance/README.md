# 治理控制台

权限体系的人工触点。独立于 `/` 上的旧工作台，由 `/governance` 托管。

## 设计取舍

页面只服务一个心智模型：**AI 停下来等我点头了**。因此收件箱是主场，其他三块是决策所需的上下文，不是并列功能。

- **审批卡的 `program + args` 是全页视觉最重的元素**。它就是要 execve 的字节，没有 shell。用深色终端块呈现，不折叠——这是被批准的东西，藏起来没道理。
- **四种卡片靠左侧色条 + 标签色区分**。一个列表混四种待办，如果类型不能一眼扫出来，操作员就得逐张读。
- **凭证库是清单，不是保险箱**。全页没有任何"查看明文/复制值"入口。解锁卡是唯一的例外，且服务端给的 `unlock_scope` 原样展示，不改写文案——"一次、同路径、只给你"三个限定一个字都不能省。
- **拒绝理由的提示写在输入框正下方**：这段话会原样发给 AI。它决定操作员写"不同意"还是写能用的原因。
- **失败不伪造**。轮询失败保留上一次数据并标示过期；解锁没拿到字节就说没拿到，不填占位符。

## 本地预览

```bash
node --check app.js
python -m http.server 8080   # 或任意静态服务器
# 打开 http://127.0.0.1:8080/index.html
```

没有后端时页面停在 Token 输入页，输入后显示连接失败——这是预期行为，不白屏。

完整联调需要主服务运行，访问 `http://<host>:<port>/governance`。

## 已知限制

- 无第三方依赖（无框架、无 CDN、无 web font），构建期工具也没用。
- 收件箱每 5 秒轮询，无 WebSocket；页面不可见时暂停。
- 名单只在 fork 时能编辑规则，不做在线规则编辑器——那已是创建新快照。
- 平台默认漂移目前只读展示差异，未做前端一键接受（后端有 `apply` 接口）。
- 重绑前会查一次影响面并提示受影响的定时任务，但该查询失败不阻止保存（只告警）。
