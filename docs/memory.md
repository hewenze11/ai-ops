# 按天分层角色记忆

更新：2026-10-03。用户需求（2026-10-02）：默认按天归档；可配置注入时间分层
（例：最近两天全文、两天前至五天前压缩、更早梗概）；角色可通过接口按需加载久远
记忆原文；角色间隔离，核心文档共享；记忆可人工编辑/删除；原始审计独立保存。

## 数据来源与真相

- **不可变真相**仍是 `role_turns`（角色轮次）与 `audit`（审计）。记忆是它们的
  派生视图，不是新的事实源；审计永不依赖模型的记忆。
- 派生行存在 `role_memory`：每个 (角色, 日期) 一行，含 `full_text`、
  `compressed`、`summary` 三种形态，以及 `source`（derived/edited）。
- 运维**编辑过**的行（`edited_at` 设置）在重建时**不会被覆盖**，人工内容优先。

## 分层策略（无重叠日期边界）

策略 `role_memory_policy` 是一组**有序、严格递增、不重叠**的分层窗口。每层覆盖
`(上一层上限, 本层上限]` 天的年龄；首层从 0 开始，末层必须开放（`max_age_days: null`），
因此每个年龄**恰好被覆盖一次**。年龄以**日历日**计算（跨零点即 +1 天），不存在
半天重叠。默认策略即用户举例：

```json
{"tiers": [
  {"max_age_days": 2,    "form": "full"},
  {"max_age_days": 5,    "form": "compressed"},
  {"max_age_days": null, "form": "summary"}
]}
```

非法策略（未开放结尾、上限非严格递增、未知 form、空列表）一律 422 拒绝。

## 注入行为

- 组装上下文时先**物化当天**行，再按年龄分层渲染。**当天不重复注入**（当前轮次已
  在实时消息里）。
- 非 full 形态的旧日期会在系统消息里以 `OLDER_MEMORY_SUMMARISED_DAYS` 列出日期，
  并说明**可经记忆接口按需取全文**——模型不应凭猜测补全。
- `compressed` 是**确定性、模型无关**的压缩（保留头尾 + 省略字数标记），
  梗概目前是粗粒度占位。**上下文路径绝不触发模型调用**：摘要由后台或人工生成，
  组装记忆不会产生意外付费调用，原文也始终可按需取回，弱摘要不会丢信息。
- 角色隔离：只读本角色自己的日期行。

## 由角色自己的模型归档（2026-10-03 用户要求）

用户要求：记忆归档是**正常的 token 消耗**，应交给**用户自己配置的那个模型**去做，
而不是固定算法。实现（`ai_ops/memory_worker.py`）分两层，安全边界如下：

- **每轮完成后异步归档**：轮次完成 → 物化当天行（写确定性 compressed/summary 作为
  **兜底**）→ 向 `memory_archive` 队列表写入一条 `pending` 作业。后台 `memory-archiver`
  线程认领作业，用**该角色的模型**把当天转写稿写成 `COMPRESSED`/`SUMMARY` 两段，
  覆盖派生形态。
- **绝不在上下文路径上调用模型**：`build_day` 只**入队**，绝不调模型；组装记忆只读已
  落盘的行。因此一轮回复永远不会为“组装记忆”产生意外付费调用。
- **绝不丢记忆**：模型未配置 / 失败 / 达到 `MAX_ATTEMPTS` 次后，保留确定性形态并把
  作业标为 `fallback`（记录 `error_code`），不会无限重试，也不会因模型挂了就没记忆。
- **不覆盖人工编辑**：`edited_at` 钉住的行，模型归档只关闭作业、不写入。
- **无工具、无权限**：归档提示词是一个封闭的摘要任务，模型在这里不能执行任何东西；
  模型 Key 只在 HTTP 边界读取。
- 运维可用 `GET /api/v1/roles/{id}/memory-archive` 查看每天是 `pending`/`archived`/
  `fallback`；可用 `AI_OPS_MEMORY_ARCHIVER_ENABLED=0` 关闭该线程。
- 确定性 `compress`/`_summarise` 仍是**兜底**形态，不再是默认最终形态。

## API（均需管理员）

- `PUT /api/v1/roles/{id}/memory/policy`、`GET …/memory/policy`
- `GET /api/v1/roles/{id}/memory`（列出各天）
- `GET /api/v1/roles/{id}/memory/{day}`：**按需加载该天全文**（不存在则按轮次物化）
- `PUT /api/v1/roles/{id}/memory/{day}`：人工编辑（钉住，重建不覆盖）
- `DELETE /api/v1/roles/{id}/memory/{day}`：删除该天记忆（**审计保留**）
- `POST /api/v1/roles/{id}/memory/rebuild`：从轮次重建所有天（编辑过的行跳过）
- `GET /api/v1/roles/{id}/memory-archive`：查看每天由模型归档的状态
  （pending/archived/fallback + 错误码）

## 与核心文档的区别

核心文档是**强制注入**、跨角色共享的；记忆是**按角色隔离、按天分层**的对话历史。
两者都在每轮注入，但语义不同，不能互相替代。

## 测试

`tests/test_memory.py`（15 项）：策略不重叠/开放结尾校验、每个年龄恰好一次、
渲染顺序与回退日期、角色隔离、编辑钉住且重建不覆盖、删除保留审计、策略 API 往返与
校验、轮次上下文注入分层且当天不重复、压缩保留头尾；**模型归档**：模型写入派生形态、
失败时降级 fallback 且不丢记忆、不覆盖人工编辑、`build_day` 只入队不调模型、
归档回复解析。
